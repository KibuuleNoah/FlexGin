# FlexGin

A production ready Go API template: Gin, PostgreSQL, sqlc, goose. Built on `go-blueprint`, reorganised so adding a feature is a short, repeatable process. `article` is the reference feature, it shows how everything must be done.

## Stack

| Concern    | Choice                                              |
|------------|-----------------------------------------------------|
| HTTP       | Gin                                                 |
| Database   | PostgreSQL via `database/sql` + `pgx/v5/stdlib`     |
| Queries    | sqlc (generated, type-safe, no ORM)                 |
| Migrations | goose                                               |
| Logging    | `log/slog` (JSON in staging/prod, text in dev)      |
| Config     | Environment variables, validated at startup         |
| Tests      | `testing`, `httptest`, testcontainers               |

## Layout

```
cmd/api/main.go          composition root: config, logger, DB, server, graceful shutdown
migrations/              goose SQL migrations (source of truth for the schema)
internal/
├── config/              typed env config, fails fast with every problem listed
├── logger/              slog setup
├── apperror/            typed errors (NotFound, Conflict, Validation, ...) -> HTTP status
├── httpx/               response envelope, binding/validation, pagination
├── middleware/          request ID, logging, recovery, CORS, timeout, error rendering
├── database/            pool setup, Health, WithTx, Postgres error helpers
├── store/               GENERATED by sqlc: models + queries for every feature
│   └── queries/         one .sql file per feature
├── server/              Server struct, route registration, probes, shutdown
└── article/             reference feature: dto, errors, service, handler, routes
```

Rules the layout follows:

- **One store.** sqlc generates a single `internal/store` package. Its models are the domain types; there is no hand-written copy.
- **Features are folders.** Each feature owns `dto.go`, `errors.go`, `service.go`, `handler.go`, `routes.go`, plus its SQL file in `internal/store/queries/`.
- **Handlers are thin.** Bind, call the service, respond. Errors are attached with `c.Error(err)` and rendered once by the error middleware.
- **Services take `store.Querier`.** Real DB in production, a fake in unit tests.

## Requirements

- Go 1.24+ (tools are pinned in `go.mod`)
- Docker (Postgres, integration tests)
- `make`

## Getting started

```sh
cp .env.example .env
make docker-run        # starts Postgres (and the app if defined in compose)
make migrate-up
make sqlc
make run
```

Check it:

```sh
curl localhost:8080/healthz
curl localhost:8080/readyz
curl -X POST localhost:8080/api/v1/articles \
  -H 'Content-Type: application/json' \
  -d '{"title":"Hello","slug":"hello","body":"First post"}'
curl 'localhost:8080/api/v1/articles?page=1&per_page=10'
```

## Configuration

All config comes from environment variables (`.env` is loaded automatically in dev). See `.env.example` for the full list.

| Variable | Default | Notes |
|---|---|---|
| `APP_ENV` | `dev` | `dev`, `staging`, `prod` |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `PORT` | `8080` | |
| `BLUEPRINT_DB_HOST` / `_PORT` / `_DATABASE` / `_USERNAME` / `_PASSWORD` / `_SCHEMA` | | host, database, username, password required |
| `DB_SSLMODE` | `disable` | rejected in `prod` |
| `DB_MAX_OPEN_CONNS` / `DB_MAX_IDLE_CONNS` | `25` | pool size |
| `HTTP_*_TIMEOUT` | see `.env.example` | read, write, idle, request, shutdown |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173` | comma-separated, `*` rejected in `prod` |

Keep comments on their own lines in `.env`. Trailing text after a value becomes part of the value.

## API

Base path: `/api/v1`. Probes live outside it.

| Method | Path | Description |
|---|---|---|
| GET | `/healthz` | liveness, no dependency checks |
| GET | `/readyz` | readiness, 503 if the DB is unreachable |
| POST | `/api/v1/articles` | create |
| GET | `/api/v1/articles` | list (`page`, `per_page`, max 100) |
| GET | `/api/v1/articles/:id` | get |
| PATCH | `/api/v1/articles/:id` | partial update |
| DELETE | `/api/v1/articles/:id` | delete |

Success:

```json
{ "data": { "id": 1, "title": "Hello" }, "meta": { "page": 1, "per_page": 20, "total": 1 } }
```

`meta` appears on list responses only.

Error:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "validation failed",
    "fields": { "slug": "is required" },
    "request_id": "9f2c..."
  }
}
```

| Kind | Status |
|---|---|
| Validation | 422 |
| NotFound | 404 |
| Conflict | 409 |
| Unauthorized / Forbidden | 401 / 403 |
| Internal | 500 (cause is logged, never returned) |

Every response carries `X-Request-ID`. A sane inbound value is reused.

## Adding a feature

Example: `cart`.

1. **Migration**
   ```sh
   make migrate-create name=create_carts
   # edit migrations/NNNNN_create_carts.sql (-- +goose Up / Down)
   make migrate-up
   ```
2. **Queries**: write `internal/store/queries/cart.sql` using `-- name: X :one|:many|:exec|:execrows`.
3. **Generate**
   ```sh
   make sqlc
   ```
   `sqlc.yaml` never changes.
4. **Feature package**: copy `internal/article` to `internal/cart` and adapt `dto.go`, `errors.go`, `service.go`, `handler.go`, `routes.go`.
5. **Wire it** (two edits):
   - `internal/server/server.go`: add the handler field and construct it with `cart.NewHandler(cart.NewService(q))`
   - `internal/server/routes.go`: add `cart.RegisterRoutes(v1, s.carts)` in `registerAPIRoutes`
6. **Test**: service tests with a fake `store.Querier`, handler tests with `httptest`.

### Transactions across features

```go
err := db.WithTx(ctx, func(tx *sql.Tx) error {
	qtx := store.New(db).WithTx(tx)
	// pass qtx to every service call that must be atomic
	return nil
})
```

## Make targets

| Target | Does |
|---|---|
| `make run` | run the API |
| `make build` | static binary `./main` |
| `make watch` | live reload with `air` |
| `make test` | all tests |
| `make itest` | integration tests (testcontainers) |
| `make lint` | golangci-lint |
| `make sqlc` / `sqlc-check` / `sqlc-vet` | generate / verify up to date / vet queries |
| `make migrate-up` / `migrate-down` / `migrate-status` / `migrate-reset` | goose |
| `make migrate-create name=...` | new migration |
| `make docker-run` / `docker-down` / `docker-build` | compose and image |
| `make clean` | clean up binary from the last build |

Tools (sqlc, goose, golangci-lint) are pinned as Go tool dependencies. First run builds them, later runs use the cache.

## Testing

- **Services**: table-driven, with an in-memory fake of `store.Querier`. Embed the interface and override only what the test uses.
- **Handlers**: `httptest` against the real service and the fake store, including the real middleware.
- **Database**: testcontainers spins up Postgres for `internal/database`.

```sh
make test
make itest
```

## Production notes

- `APP_ENV=prod` requires `DB_SSLMODE` other than `disable` and an explicit CORS origin list.
- Use `/healthz` for liveness and `/readyz` for readiness in your orchestrator.
- SIGINT/SIGTERM triggers graceful shutdown: in-flight requests drain within `HTTP_SHUTDOWN_TIMEOUT`, then the pool closes.
- Run `make migrate-up` as a deploy step, not at app startup.
- CI should run `make sqlc-check`, `make lint`, and `make test`.
